00

Apprendre à penser comme un développeur

Avant même d'écrire une ligne de Go, il faut installer dans ta tête une nouvelle façon de raisonner. C'est le module le plus important du cours - celui que tout le monde a envie de sauter, et celui qui te sauvera le plus de fois.

00.1

Qu'est-ce qu'un programme ?

Le problème de la vraie vie

Imagine que tu es un cuisinier. On te donne des ingrédients (des œufs, de la farine), tu les transformes (tu mélanges, tu cuis), et tu obtiens un résultat (une crêpe). Un programme informatique fait exactement pareil, sauf qu'au lieu d'ingrédients il prend des données : ce que tape l'utilisateur, un fichier, l'heure du système... Il les transforme avec des calculs et des règles, et il produit un résultat : un message affiché, un fichier sauvegardé, un jeu qui réagit.

Sans cette idée en tête, on code "au hasard". Avec elle, face à n'importe quel exercice, tu te poses toujours la même question en 3 temps : qu'est-ce qui rentre ? qu'est-ce qu'on en fait ? qu'est-ce qui doit sortir ?

Exemples progressifs
1 · le plus simple

Un programme qui n'a même pas d'entrée : il sort toujours la même chose.

package main import "fmt" func main() { fmt.Println("Bonjour Ynov !") // Sortie fixe, aucune Entrée }
2 · cas concret

Cette fois, il y a une vraie Entrée : le prénom tapé au clavier.

package main import "fmt" func main() { var prenom string // ENTRÉE : une boîte vide pour stocker le prénom fmt.Scan(&prenom) // on remplit la boîte avec la saisie clavier fmt.Println("Salut", prenom) // TRAITEMENT + SORTIE }
3 · cas limite

Et si l'utilisateur n'entre rien du tout (il appuie juste sur Entrée) ?

var prenom string fmt.Scan(&prenom) // Scan attend un "mot" : tant qu'aucun caractère n'est tapé, // le programme reste bloqué ici. Ce n'est pas un bug : c'est // l'ordinateur qui respecte l'ordre "attends une Entrée".
Ce qu'il faut retenir

Un programme est toujours à l'écoute de son Entrée. Si l'Entrée ne vient jamais, le Traitement ne démarre jamais, et il n'y a jamais de Sortie. C'est pour ça qu'on apprendra bientôt à valider les saisies (module 04.5).

00.2

Diviser pour régner (Divide & Conquer)

Le problème de la vraie vie

Demande à quelqu'un "range ta chambre" en une seule instruction géante : il/elle bloque, ne sait pas par où commencer. Mais découpe en "range les vêtements", "fais le lit", "range le bureau" : chaque étape devient faisable toute seule. Un programme, c'est pareil. "Faire un jeu de devinette" est trop gros pour être codé d'un bloc. On le découpe en petites tâches, chacune assez simple pour tenir dans une fonction.

Exemples progressifs
1 · le plus simple

Problème : "afficher la table de multiplication de 7".

  • Sous-problème A : choisir un nombre de départ (1)
  • Sous-problème B : le multiplier par 7 et l'afficher
  • Sous-problème C : répéter jusqu'à 10
2 · cas concret

Problème : "Projet RED - un mini-jeu textuel".

  • Afficher un menu (fonction afficherMenu())
  • Lire le choix du joueur (fonction lireChoix())
  • Exécuter l'action correspondante (fonction jouerTour())
  • Vérifier si la partie est finie (fonction estTermine())

Chaque fonction est un petit "range ta chambre" gérable tout seul. Le main() ne fait qu'appeler ces fonctions dans le bon ordre.

3 · cas limite

Piège inverse : découper à l'excès. Une fonction ajouterUn(x int) int { return x + 1 } pour une seule addition simple ajoute de la complexité inutile. Le découpage sert quand une tâche a plusieurs étapes ou sera réutilisée - pas pour chaque ligne isolée.

00.3

Le pseudo-code

Le problème de la vraie vie

Un architecte ne pose pas les premières briques avant d'avoir dessiné le plan. Le pseudo-code est ce plan : tu écris ta logique en français, sans te soucier des points-virgules ni des accolades. Ça te force à réfléchir à l'algorithme avant de te battre avec la syntaxe - les deux problèmes ne sont jamais mélangés.

Exemples progressifs
1 · le plus simple
DÉBUT DEMANDER l'âge SI âge >= 18 ALORS AFFICHER "Majeur" SINON AFFICHER "Mineur" FIN
2 · cas concret

Pseudo-code d'une calculatrice (module 03) :

DÉBUT DEMANDER nombre1 DEMANDER nombre2 DEMANDER opération (+ - * /) SI opération = "/" ET nombre2 = 0 ALORS AFFICHER "Erreur : division par zéro" SINON CALCULER résultat selon opération AFFICHER résultat FIN SI FIN
3 · cas limite

Pseudo-code d'une boucle de menu qui ne s'arrête que sur demande explicite - le cas "répéter indéfiniment" est le piège classique des débutants (on oublie souvent la condition de sortie) :

DÉBUT TANT QUE l'utilisateur n'a pas choisi "Quitter" AFFICHER menu LIRE choix TRAITER choix FIN TANT QUE FIN

00.4

Lire une erreur de compilation sans paniquer

Le problème de la vraie vie

Une erreur de compilation, c'est comme un GPS qui te dit "tourne à gauche dans 200m" : ce n'est pas une punition, c'est une indication précise de où corriger. Les débutants paniquent et réécrivent tout ; les développeurs expérimentés lisent calmement et corrigent un détail.

Exemples progressifs
1 · le plus simple
./main.go:5:2: undefined: fmt.Pritnln
  • main.go:5:2fichier main.go, ligne 5, colonne 2 - l'endroit exact du problème.
  • undefinedGo ne connaît pas ce nom - faute de frappe probable : Pritnln au lieu de Println.
    • 2 · cas concret
    ./main.go:8:14: cannot use age (variable of type string) as int value

    Traduction : à la ligne 8, colonne 14, tu essaies d'utiliser age qui est un string (texte) là où Go attend un int (nombre). Solution : convertis avec strconv.Atoi (module 01.6).

    3 · cas limite

    Erreurs en cascade : une seule faute (ex. accolade { oubliée) peut générer 10 lignes d'erreurs différentes plus bas. Toujours corriger la première erreur du haut, recompiler, et regarder ce qu'il en reste - souvent les 9 autres disparaissent toutes seules.

    Piège classique

    Copier-coller le message d'erreur dans un moteur de recherche sans l'avoir lu. Prends 5 secondes : fichier, ligne, et le mot-clé du message (undefined, cannot use, expected...) te disent déjà 80% du problème.

    Quiz éclair

    Tu vois « ./main.go:12:3: undefined: tot ». Que fais-tu en premier ?

    01

    Les fondations en Go

    Maintenant que tu penses en Entrée → Traitement → Sortie, on va écrire les premières vraies briques : le squelette d'un fichier Go, les variables, les types, et comment parler avec l'utilisateur.

    01.1

    Structure minimale d'un fichier Go

    Le problème de la vraie vie

    Une lettre a besoin d'une adresse, d'un en-tête et d'un corps pour être livrée et comprise. Un fichier Go a besoin de la même structure minimale pour que l'ordinateur sache : d'où partir, quels outils charger, et quoi exécuter en premier.

    Décorticage mot par mot
    package main import "fmt" func main() { fmt.Println("Bonjour Ynov !") }
    • package mainChaque fichier Go appartient à un paquet (un groupe de fichiers). main est un nom spécial : il dit à Go "ce paquet doit produire un programme qu'on peut lancer" (et non une simple bibliothèque).
    • import "fmt"import = "j'ai besoin d'emprunter des outils". "fmt" est le nom de la boîte à outils qui sait afficher du texte à l'écran (format).
    • func main()func = "je déclare une fonction". main est le nom réservé de la fonction que Go exécute en premier, automatiquement, quand tu lances le programme.
    • { }Les accolades délimitent le corps de la fonction : tout ce qui doit s'exécuter quand on l'appelle est entre elles.
    • fmt.Println(...)Le point . veut dire "va chercher Println à l'intérieur de la boîte à outils fmt". Println affiche le texte puis passe à la ligne suivante.
    Comment lancer vraiment ce fichier

    Écris ce code dans un fichier nommé main.go, puis ouvre un terminal dans ce dossier et tape :

    go run main.go

    go run compile ET exécute en une seule commande - idéal pendant que tu apprends. Quand ton programme est prêt à être distribué, go build compile un fichier exécutable autonome (.exe sous Windows) que tu peux lancer sans avoir Go installé.

    go build main.go ./main // ou main.exe sous Windows
    Exemples progressifs
    1 · le plus simple
    package main import "fmt" func main() { fmt.Println("Bonjour Ynov !") }
    2 · cas concret

    Deux affichages successifs - l'ordre d'écriture = l'ordre d'exécution :

    package main import "fmt" func main() { fmt.Println("Chargement du programme...") fmt.Println("Prêt.") }
    3 · cas limite

    Import inutilisé - Go est strict, il refuse de compiler :

    import "fmt" // importé... func main() { // ...mais jamais utilisé plus bas ! } // Erreur : "fmt" imported and not used
    Piège classique

    En Go, contrairement à d'autres langages, un import ou une variable déclarée et jamais utilisée est une erreur de compilation, pas juste un avertissement. Le programme ne compile pas du tout tant que ce n'est pas corrigé.

    Quiz éclair

    Tu importes "fmt" mais tu ne l'utilises nulle part dans le fichier. Que se passe-t-il ?

    01.2

    Variables (var, :=) et constantes (const)

    Le problème de la vraie vie

    Sans variable, ton programme est amnésique : il ne peut rien retenir entre deux lignes. Une variable est une boîte étiquetée en mémoire : tu lui donnes un nom, tu ranges une valeur dedans, et tu peux la relire ou la remplacer plus tard. Une constante, c'est la même boîte mais scellée à la colle : une fois remplie, personne ne peut changer son contenu (utile pour un taux de TVA, un nombre Pi, un nombre max de joueurs...).

    Décorticage mot par mot
    var nom string = "Léa" age := 20 const Pi = 3.14159
    • var"Je déclare une variable." Utilisable partout (même hors d'une fonction), et permet d'annoncer le type avant de donner la valeur.
    • nom stringLe nom de la boîte est nom, son type est string (texte) - Go doit toujours savoir le type d'une boîte pour l'utiliser correctement.
    • = "Léa"On range la valeur "Léa" dans la boîte au moment de sa création.
    • :=Le raccourci "déclare-ET-remplis en même temps, devine le type toi-même". Go voit 20 et déduit tout seul que c'est un int. Ne fonctionne qu'à l'intérieur d'une fonction.
    • const"Je déclare une boîte scellée." Sa valeur est fixée à l'écriture du code et ne peut jamais être réaffectée, sinon erreur de compilation.
    Exemples progressifs
    1 · le plus simple
    age := 20 fmt.Println(age) // affiche 20 age = 21 // on remplace le contenu de la boîte fmt.Println(age) // affiche 21
    Bac à sablechange la valeur de age, ou le texte, puis Exécuter
    age := 20 fmt.Println(age) age = 21 fmt.Println(age)
    2 · cas concret

    Un score de jeu qui évolue, et une constante de configuration qui ne bouge jamais :

    const VieMax = 100 // règle du jeu, jamais modifiée vieJoueur := VieMax vieJoueur -= 30 // le joueur prend 30 dégâts fmt.Println("Vie :", vieJoueur, "/", VieMax)
    3 · cas limite

    Essayer de modifier une constante - Go refuse à la compilation :

    const Pi = 3.14159 Pi = 3.14 // ERREUR : cannot assign to Pi (constant)
    Piège classique

    Utiliser := une deuxième fois sur la même variable dans le même bloc → erreur no new variables on left side of :=. Une fois la boîte créée, on la remplit avec = tout simplement, plus :=.

    Quiz éclair

    x a déjà été créée avec x := 5. Comment lui donner la valeur 10 juste après ?

    01.3

    Types de base : int, float64, string, bool

    Le problème de la vraie vie

    Dans un tiroir à couverts, on ne range pas les fourchettes avec les verres : chaque chose a sa case pour éviter la pagaille. Le type d'une variable, c'est cette case : Go doit savoir si une boîte contient un nombre entier, un nombre à virgule, du texte ou un vrai/faux, pour savoir quelles opérations sont permises (additionner deux int : oui ; additionner un texte et un nombre directement : non).

    Exemples progressifs
    1 · le plus simple
    var age int = 20 var prix float64 = 19.99 var nom string = "Ynov" var estMajeur bool = true
    2 · cas concret

    Un panier d'e-commerce simplifié :

    prixUnitaire := 12.50 quantite := 3 total := prixUnitaire * float64(quantite) enStock := true fmt.Println("Total :", total, "| Dispo :", enStock)
    Bac à sablemodifie les valeurs, clique Exécuter
    prixUnitaire := 12.50 quantite := 3 total := prixUnitaire * float64(quantite) fmt.Println("Total :", total)
    3 · cas limite

    Mélanger les types directement - Go refuse, contrairement à des langages plus permissifs :

    quantite := 3 // int prix := 12.50 // float64 total := prix * quantite // ERREUR : mismatched types float64 and int
    Piège classique

    Go ne convertit jamais automatiquement un type dans un autre, même si "ça a l'air logique". Il faut toujours convertir explicitement : prix * float64(quantite). C'est plus verbeux, mais ça évite des bugs silencieux fréquents dans d'autres langages.

    Quiz éclair

    prix (float64) et quantite (int). Que se passe-t-il avec prix * quantite sans conversion ?

    01.4

    La portée des variables (scope)

    Le problème de la vraie vie

    Ce que tu dis dans une pièce fermée ne s'entend pas dans la pièce d'à côté. Une variable créée à l'intérieur d'un bloc { } "vit" seulement dans ce bloc : dès que l'accolade se ferme, elle disparaît de la mémoire. C'est une protection, pas une contrainte : ça évite que deux bouts de code différents se marchent dessus par erreur avec le même nom de variable.

    Décorticage mot par mot
    if x > 5 { y := "visible ici seulement" }
    • if x > 5 {Ouvre un nouveau bloc. Tout ce qui est déclaré dedans appartient à ce bloc.
    • y := ...La boîte y naît à l'intérieur du bloc if.
    • }Accolade fermante = fin du bloc = y est détruite. Elle n'existe plus une seule ligne plus bas.
    Exemples progressifs
    1 · le plus simple
    func main() { x := 10 if x > 5 { y := "visible ici" fmt.Println(y) } fmt.Println(y) // ERREUR : undefined: y }
    2 · cas concret

    Solution : déclarer la variable avant le bloc si on veut la garder après :

    func main() { var resultat string // déclarée au niveau de main if age >= 18 { resultat = "Majeur" // = pas :=, on remplit la boîte existante } else { resultat = "Mineur" } fmt.Println(resultat) // fonctionne : resultat vit dans main }
    Bac à sablechange age ou le seuil 18, observe la branche exécutée
    var resultat string age := 20 if age >= 18 { resultat = "Majeur" } else { resultat = "Mineur" } fmt.Println(resultat)
    3 · cas limite

    Deux variables de même nom dans deux scopes différents ne se confondent jamais - la plus "proche" gagne :

    x := "extérieur" if true { x := "intérieur" // nouvelle boîte, masque la première fmt.Println(x) // affiche "intérieur" } fmt.Println(x) // affiche "extérieur", inchangée
    Piège classique

    Croire qu'on modifie la variable extérieure avec := à l'intérieur d'un bloc. En réalité := crée une toute nouvelle boîte qui masque temporairement l'ancienne, sans jamais la toucher.

    Quiz éclair

    Une variable créée avec := à l'intérieur d'un if existe-t-elle encore après le } fermant ?

    01.5

    Afficher et saisir : Println, Printf, Scan

    Le problème de la vraie vie

    Un programme muet et sourd ne sert à rien : il doit pouvoir parler (afficher) et écouter (saisir) pour interagir avec un humain. Println/Printf sont la bouche, Scan est l'oreille.

    Décorticage mot par mot
    fmt.Printf("Salut %s, tu as %d ans\n", prenom, age) fmt.Scan(&prenom)
    • Printf"Print + Format" : affiche une phrase avec des trous à remplir.
    • %s / %d%s = trou pour un string, %d = trou pour un nombre entier (decimal). Chaque trou est rempli, dans l'ordre, par les arguments après la phrase.
    • \nCaractère spécial "retour à la ligne" - Printf, contrairement à Println, ne saute pas de ligne tout seul.
    • &prenomLe & veut dire "l'adresse de la boîte prenom", pas son contenu. Scan a besoin de savoir où écrire la saisie, donc où se trouve la boîte physiquement en mémoire (approfondi en 06.1).
    Exemples progressifs
    1 · le plus simple
    var age int fmt.Print("Ton âge : ") fmt.Scan(&age) fmt.Println("Tu as", age, "ans")
    2 · cas concret

    Formatage propre d'une fiche joueur avec Printf :

    nom := "Yanis" niveau := 7 pv := 85.5 fmt.Printf("%s | Niveau %d | PV: %.1f\n", nom, niveau, pv)
    Simulateur d'exécution
    Trou Type attendu Valeur insérée
    %s string Yanis
    %d int 7
    %.1f float, 1 décimale 85.5

    Résultat écran : Yanis | Niveau 7 | PV: 85.5

    3 · cas limite

    Mauvais type de trou pour la valeur - le programme compile mais affiche n'importe quoi :

    age := 20 fmt.Printf("Âge : %s\n", age) // %s attend un string, age est un int // Écran : Âge : %!s(int=20) ← Go signale l'incohérence
    Piège classique

    Oublier & devant une variable dans Scan. Sans &, Go donne une copie de la valeur au lieu de son adresse : Scan écrit dans le vide, et la variable originale reste inchangée.

    Les verbes qui sauvent quand tu hésites

    Pas besoin de connaître %s/%d/%f par cœur dès le premier jour. Deux verbes universels dépannent dans presque tous les cas :

    age := 20 nom := "Léa" fmt.Printf("%v %v\n", nom, age) // %v = "valeur", marche avec N'IMPORTE quel type fmt.Printf("%T %T\n", nom, age) // %T = affiche le TYPE de la variable // Écran : Léa 20 // string int

    %v est ton filet de sécurité : utilise-le pour explorer/déboguer rapidement, puis affine avec %s/%d/%.2f quand tu veux un affichage précis pour l'utilisateur final.

    Quiz éclair

    Pourquoi écrit-on fmt.Scan(&age) et pas fmt.Scan(age) ?

    01.6

    Conversion de types : strconv.Atoi / Itoa

    Le problème de la vraie vie

    Tout ce qu'un utilisateur tape au clavier arrive toujours sous forme de texte, même s'il tape des chiffres. Pour calculer avec ces chiffres, il faut d'abord "traduire" le texte en vrai nombre - comme un douanier qui convertit des devises avant de pouvoir additionner deux prix de pays différents.

    Décorticage mot par mot
    nombre, err := strconv.Atoi("42")
    • strconvLa boîte à outils "string conversion" - à importer avec import "strconv".
    • Atoi"ASCII to Integer" : transforme un texte en nombre entier.
    • nombre, err :=Atoi renvoie deux valeurs à la fois : le nombre converti, et une erreur (nil si tout va bien). On les récupère toutes les deux d'un coup - approfondi en 03.3/03.4.
    Exemples progressifs
    1 · le plus simple
    texte := "42" nombre, err := strconv.Atoi(texte) fmt.Println(nombre, err)
    2 · cas concret

    Reconvertir un nombre en texte pour l'afficher dans une phrase construite avec des + :

    score := 150 phrase := "Ton score : " + strconv.Itoa(score) fmt.Println(phrase)
    3 · cas limite

    L'utilisateur tape du texte non numérique - Atoi renvoie une erreur au lieu de planter :

    nombre, err := strconv.Atoi("abc") if err != nil { fmt.Println("Ce n'est pas un nombre valide !") return } fmt.Println(nombre) // jamais atteint si err != nil
    Piège classique

    Ignorer err avec _ pour "aller plus vite" (nombre, _ := strconv.Atoi(texte)). Si la conversion échoue, nombre vaut 0 silencieusement - un bug très difficile à repérer plus tard, car le programme ne plante pas, il calcule juste faux.

    Quiz éclair

    Que vaut nombre après nombre, _ := strconv.Atoi("abc") ?

    02

    Décider et répéter

    Jusqu'ici ton programme exécutait toujours la même suite de lignes. Ce module lui apprend à choisir son chemin et à répéter des actions - c'est ce qui transforme une liste d'instructions figée en un vrai programme réactif.

    02.1

    Opérateurs de comparaison et logiques

    Le problème de la vraie vie

    Avant de décider quoi que ce soit, il faut pouvoir poser une question fermée : est-ce plus grand ? est-ce égal ? est-ce que les deux conditions sont vraies en même temps ? Les opérateurs de comparaison (==, !=, <, >...) sont ces questions ; les opérateurs logiques (&&, ||, !) permettent de les combiner, comme "il faut avoir 18 ans ET une pièce d'identité" pour rentrer en boîte.

    Décorticage mot par mot
    age >= 18 && aCarte == true
    • >="Plus grand ou égal à" - renvoie un bool (true/false), jamais un nombre.
    • =="Est égal à" - attention, un seul = veut dire "range la valeur", deux == veulent dire "compare". Confondre les deux est l'erreur n°1 des débutants dans beaucoup de langages (Go, lui, refuse carrément de compiler if x = 5).
    • &&"ET" logique : vrai seulement si les deux côtés sont vrais.
    • ||"OU" logique : vrai si au moins un des deux côtés est vrai.
    • !"NON" : inverse un bool. !true devient false.
    Exemples progressifs
    1 · le plus simple
    a := 5 b := 10 fmt.Println(a < b) // true fmt.Println(a == b) // false
    2 · cas concret

    L'accès à une boîte de nuit : il faut être majeur ET avoir sa carte d'identité.

    age := 20 aCarte := true peutEntrer := age >= 18 && aCarte fmt.Println(peutEntrer)
    3 · cas limite

    Une seule des deux conditions suffit à tout faire basculer avec && :

    age := 20 aCarte := false // carte oubliée ! peutEntrer := age >= 18 && aCarte fmt.Println(peutEntrer) // false, malgré l'âge suffisant
    Piège classique

    Écrire if x = 5 au lieu de if x == 5. En Go cette confusion est bloquée à la compilation (contrairement à certains langages où elle crée un bug silencieux), mais le réflexe "deux égales pour comparer" doit devenir automatique.

    Bac à sablechange age / aCarte, observe le résultat
    age := 20 aCarte := true peutEntrer := age >= 18 && aCarte fmt.Println(peutEntrer)
    Quiz éclair

    age >= 18 vaut true, aCarte vaut false. Que vaut age >= 18 && aCarte ?

    02.2

    Les conditions : if / else if / else

    Le problème de la vraie vie

    Un distributeur de billets ne fait pas la même chose selon que ton solde est suffisant ou non. if est ce carrefour : "SI cette question est vraie, prends ce chemin ; SINON, prends l'autre." Sans lui, ton programme ferait toujours exactement la même chose, quelle que soit la situation.

    Décorticage mot par mot
    if note >= 16 { fmt.Println("Félicitations") } else if note >= 10 { fmt.Println("Admis") } else { fmt.Println("À revoir") }
    • if"Si" - pose une question à l'ordinateur. Si la réponse est vraie, le bloc { } qui suit s'exécute.
    • (condition)La question elle-même - doit toujours évaluer à un bool.
    • { }"Alors fais tout ce qui est dedans" - le corps du bloc.
    • else if"Sinon, si..." - une question de secours, testée seulement si la précédente était fausse.
    • else"Sinon" - le cas par défaut, exécuté seulement si aucune condition au-dessus n'était vraie.
    Exemples progressifs
    1 · le plus simple
    age := 16 if age >= 18 { fmt.Println("Majeur") } else { fmt.Println("Mineur") }
    2 · cas concret

    Un système de notation à trois niveaux - l'ordre des if compte :

    note := 12 if note >= 16 { fmt.Println("Félicitations") } else if note >= 10 { fmt.Println("Admis") } else { fmt.Println("À revoir") }
    3 · cas limite

    Inverser l'ordre des conditions change tout - un piège très classique :

    note := 18 if note >= 10 { fmt.Println("Admis") // ⚠ cette condition est testée en premier... } else if note >= 16 { fmt.Println("Félicitations") // ...jamais atteinte, même avec 18 ! }
    Piège classique

    Go teste les conditions dans l'ordre d'écriture et s'arrête à la première vraie. Si tu mets la condition la plus large en premier, les cas plus précis en dessous ne sont jamais atteints. Range toujours les if/else if du cas le plus restrictif au plus large.

    Bac à sablechange la note, observe quelle branche s'exécute
    note := 12 resultat := "" if note >= 16 { resultat = "Felicitations" } else { resultat = "A revoir" } fmt.Println(resultat)

    Ce bac à sable simplifié ne gère que if/else (2 branches) - le vrai else if est visible dans le simulateur ci-dessus.

    Quiz éclair

    if note >= 10 {...} else if note >= 16 {...} - avec note = 18, quelle branche s'exécute ?

    02.3

    Les choix multiples : switch

    Le problème de la vraie vie

    Un menu de restaurant avec 8 plats écrit en if / else if / else if / else if... devient illisible. switch est fait pour ça : "selon la valeur exacte de cette variable, va directement dans la bonne case" - comme un standardiste qui redirige un appel selon le numéro de poste demandé, sans tester 8 conditions une par une.

    Décorticage mot par mot
    switch choix { case 1: fmt.Println("Ajouter") case 2: fmt.Println("Supprimer") default: fmt.Println("Choix invalide") }
    • switch choix {"Regarde la valeur de choix, et compare-la à chaque cas ci-dessous."
    • case 1:"Si choix vaut exactement 1..." - pas besoin d'écrire choix ==, switch compare tout seul.
    • (pas de break)Contrairement à d'autres langages, Go s'arrête automatiquement à la fin de chaque case - pas besoin d'écrire break, et il n'y a pas de "fall-through" accidentel vers le case suivant.
    • default:Le cas "sinon, si rien n'a matché" - équivalent du else final, optionnel mais recommandé.
    Exemples progressifs
    1 · le plus simple
    jour := 3 switch jour { case 1: fmt.Println("Lundi") case 2: fmt.Println("Mardi") case 3: fmt.Println("Mercredi") }
    2 · cas concret

    Un menu interactif avec cas par défaut :

    choix := 9 switch choix { case 1: fmt.Println("Ajouter un joueur") case 2: fmt.Println("Supprimer un joueur") default: fmt.Println("Choix invalide") }
    3 · cas limite

    Regrouper plusieurs valeurs dans un seul case (séparées par des virgules) :

    jour := 6 switch jour { case 6, 7: fmt.Println("Week-end") // se déclenche pour 6 OU 7 default: fmt.Println("Jour ouvré") }
    Piège classique

    Croire qu'un case Go "tombe" dans le suivant comme en C ou en JavaScript sans break. En Go c'est l'inverse : chaque case s'arrête tout seul, et si tu veux vraiment enchaîner sur le case suivant il faut le mot-clé explicite fallthrough (rarement utilisé).

    Quiz éclair

    En Go, faut-il écrire break à la fin de chaque case d'un switch ?

    02.4

    La boucle for (1/3) - comptée

    Le problème de la vraie vie

    Faire 10 pompes, c'est répéter le même mouvement 10 fois en comptant. Une boucle comptée fait pareil : "répète ce bloc, en comptant, jusqu'à atteindre une limite précise." Sans elle, il faudrait copier-coller la même ligne 10 fois - imagine pour 1000 fois.

    Décorticage mot par mot
    for i := 0; i < 5; i++ { fmt.Println("Tour numéro", i) }
    • for"Répète" - Go n'a qu'un seul mot-clé pour toutes les boucles, contrairement à d'autres langages qui ont for/while/do-while séparés.
    • i := 0L'initialisation : exécutée une seule fois, avant le premier tour. Crée le compteur.
    • i < 5La condition : vérifiée avant chaque tour. Tant qu'elle est vraie, la boucle continue.
    • i++Le pas : exécuté après chaque tour, avant de re-vérifier la condition. i++ = "ajoute 1 à i".
    Exemples progressifs
    1 · le plus simple
    for i := 0; i < 3; i++ { fmt.Println(i) }
    2 · cas concret

    Afficher la table de multiplication de 7 (module 00.2) :

    for i := 1; i <= 10; i++ { fmt.Println(7, "x" , i, "=" , 7*i) }
    3 · cas limite

    Une erreur de condition qui ne boucle jamais :

    for i := 10; i < 5; i++ { fmt.Println(i) // jamais exécuté ! } // i vaut déjà 10, et 10 < 5 est faux dès le départ
    Piège classique

    Oublier que la condition est vérifiée avant le premier tour aussi. Si elle est fausse dès le départ, le corps de la boucle ne s'exécute jamais, pas même une fois.

    02.5

    La boucle for (2/3) - conditionnelle

    Le problème de la vraie vie

    Parfois tu ne sais pas à l'avance combien de fois répéter - tu veux juste continuer "tant qu'une condition tient", comme "continue à courir tant que tu as de l'énergie". C'est le rôle du for sans compteur explicite : l'équivalent du while d'autres langages.

    Décorticage mot par mot
    for energie > 0 { energie-- }
    • for energie > 0Une seule condition, pas d'initialisation ni de pas inscrits sur cette ligne - mais il faut bien que energie soit créée avant, et modifiée dans le corps, sinon boucle infinie.
    • energie--"Retire 1 à energie" - c'est ce qui fait progresser la boucle vers sa fin.
    Exemples progressifs
    1 · le plus simple
    energie := 3 for energie > 0 { fmt.Println("Énergie :", energie) energie-- }
    2 · cas concret

    Vider une jauge de vie jusqu'à zéro, tour de jeu par tour de jeu :

    vie := 40 degats := 15 for vie > 0 { vie -= degats fmt.Println("Vie restante :", vie) }
    3 · cas limite

    Oublier de faire progresser la variable de condition :

    energie := 3 for energie > 0 { fmt.Println("Encore de l'énergie") // energie-- oublié ! } // energie reste toujours à 3 → boucle infinie
    Piège classique

    C'est LE piège n°1 des boucles conditionnelles : si rien à l'intérieur du corps ne fait évoluer la variable testée, la condition reste vraie pour toujours et le programme se fige. Toujours vérifier : "qu'est-ce qui, dans ce corps, rapproche la condition de sa sortie ?"

    Quiz éclair

    for energie > 0 { fmt.Println("...") } - sans energie-- dans le corps, que se passe-t-il ?

    02.6

    La boucle for (3/3) - infinie + break/continue

    Le problème de la vraie vie

    Un jeu tourne "tant que le joueur n'a pas quitté" - une condition qui dépend d'un événement futur, pas d'un compteur connu à l'avance. for {} (sans aucune condition) boucle pour toujours, et break devient la seule porte de sortie - comme une réunion sans heure de fin prévue, qui ne s'arrête que quand quelqu'un se lève et dit "stop".

    Décorticage mot par mot
    for { if fini { break } if pause { continue } }
    • for {Aucune condition = "répète pour toujours", sauf instruction contraire à l'intérieur.
    • break"Casse la boucle" - sort immédiatement et complètement de la boucle, même si on est en plein milieu du corps.
    • continue"Passe au tour suivant" - arrête le tour actuel sans quitter la boucle, retourne directement au début du prochain tour.
    Exemples progressifs
    1 · le plus simple
    i := 0 for { if i >= 3 { break } fmt.Println(i) i++ }
    2 · cas concret

    Sauter les nombres pairs avec continue, s'arrêter à 7 avec break :

    i := 0 for { i++ if i%2 == 0 { continue // saute l'affichage pour les pairs } if i > 7 { break } fmt.Println(i) }
    3 · cas limite

    Un for {} sans aucune condition de sortie :

    for { fmt.Println("encore...") // aucun break nulle part } // tourne pour toujours, le programme ne répond plus
    Piège classique

    C'est le piège déjà annoncé en 00.3 et 02.5, sous sa forme la plus radicale : un for {} sans aucun break atteignable ne s'arrête jamais. Avant d'écrire for {}, demande-toi toujours : "dans quelle condition est-ce que je sors ?"

    Quelle est la différence entre continue et break dans une boucle ?

    03.2

    Découper son code : créer et appeler une fonction

    Le problème de la vraie vie

    Une recette de cuisine qu'on utilise souvent (une pâte à crêpes), on ne la réécrit pas à chaque fois : on la note une fois, et on s'y réfère. Une fonction, c'est exactement ça - une suite d'instructions nommée et réutilisable, qu'on appelle par son nom au lieu de recopier son code partout.

    Décorticage mot par mot
    func addition(a int, b int) int { return a + b }
    • func"Je déclare une fonction" - déjà vu avec func main(), mais ici on donne un nom personnalisé.
    • additionLe nom de la fonction - choisis-le pour qu'il dise ce qu'elle fait.
    • (a int, b int)Les paramètres : des boîtes vides que l'appelant remplira au moment de l'appel.
    • int(après la parenthèse) Le type de retour : ce que la fonction va renvoyer à celui qui l'appelle.
    • return"Renvoie cette valeur et termine immédiatement la fonction."
    Exemples progressifs
    1 · le plus simple
    func direBonjour() { fmt.Println("Bonjour !") } func main() { direBonjour() // appel : exécute le corps de la fonction }
    2 · cas concret
    func addition(a int, b int) int { return a + b } func main() { resultat := addition(4, 7) fmt.Println(resultat) // 11 }
    3 · cas limite

    Une fonction qui déclare un type de retour doit toujours renvoyer une valeur sur tous les chemins possibles :

    func diviser(a, b int) int { if b != 0 { return a / b } // ERREUR : missing return - et si b == 0 ? }
    Piège classique

    Oublier un return pour un chemin possible. Go refuse de compiler si un chemin du code peut sortir de la fonction sans renvoyer la valeur promise.

    Quiz éclair

    03.3

    Paramètres et retours multiples

    Le problème de la vraie vie

    Demande "quelle heure est-il et quel jour sommes-nous ?" - une seule réponse ne suffit pas, il en faut deux en même temps. Une fonction Go peut renvoyer plusieurs valeurs à la fois, ce qui est rare dans d'autres langages mais très naturel en Go - notamment pour renvoyer "le résultat, ET une erreur éventuelle" en un seul geste.

    Décorticage mot par mot
    func diviser(a, b float64) (float64, error) { if b == 0 { return 0, errors.New("division par zéro") } return a / b, nil }
    • a, b float64Deux paramètres du même type peuvent partager un seul float64 au lieu de le répéter.
    • (float64, error)Type de retour double, entre parenthèses : la fonction renverra toujours deux valeurs, dans cet ordre.
    • errors.New(...)Crée une nouvelle erreur avec un message - nécessite import "errors".
    • nil"Rien" / "aucune erreur" - la valeur zéro spéciale pour dire "tout s'est bien passé".
    Exemples progressifs
    1 · le plus simple
    func minEtMax(a, b int) (int, int) { if a < b { return a, b } return b, a } petit, grand :=minEtMax(9, 3)
    2 · cas concret
    resultat, err := diviser(10, 2) fmt.Println(resultat, err)
    3 · cas limite
    resultat, err := diviser(10, 0) fmt.Println(resultat, err)
    Piège classique

    Oublier de récupérer une des deux valeurs de retour - Go exige que tu récupères toutes les valeurs renvoyées (ou explicitement avec _ celles que tu ignores volontairement).

    Le bonus caché de l'affectation multiple

    Puisque Go sait affecter plusieurs valeurs d'un coup (a, b := ...), il peut échanger deux variables sans boîte temporaire - contrairement à la plupart des langages où il faut une 3e variable intermédiaire :

    a, b := 1, 2 a, b = b, a // échange direct, sans variable temporaire fmt.Println(a, b) // 2 1

    Le membre de droite b, a est entièrement évalué avec les anciennes valeurs avant que Go ne les range dans a et b - c'est ce qui rend l'échange direct possible.

    03.4

    Gestion d'erreurs idiomatique : if err != nil

    Le problème de la vraie vie

    Un livreur qui ne peut pas livrer un colis (adresse introuvable) ne fait pas semblant que tout va bien : il te prévient. En Go, une erreur est une valeur ordinaire qu'on vérifie juste après chaque opération risquée - pas un mécanisme caché qui interrompt le programme sans prévenir.

    Exemples progressifs
    1 · le plus simple
    resultat, err := diviser(10, 0) if err != nil { fmt.Println("Erreur :", err) return } fmt.Println("Résultat :", resultat)
    2 · cas concret

    Le même code, mais avec une division valide - la branche d'erreur n'est jamais prise :

    resultat, err := diviser(10, 2) if err != nil { fmt.Println("Erreur :", err) return } fmt.Println("Résultat :", resultat) // atteint cette fois
    3 · cas limite

    Vérifier l'erreur mais oublier le return :

    resultat, err := diviser(10, 0) if err != nil { fmt.Println("Erreur :", err) // return manquant ! } fmt.Println("Résultat :", resultat) // s'exécute quand même, affiche 0
    Piège classique

    Vérifier err sans jamais return (ou continue/break selon le contexte). Le programme continue alors avec des données invalides (ici resultat = 0) comme si de rien n'était.

    03.5

    L'instruction defer

    Le problème de la vraie vie

    Quand tu ouvres une porte de frigo, tu sais que tu devras la refermer, même si tu ne sais pas encore exactement quand. defer fait cette promesse à Go : "quoi qu'il arrive dans cette fonction, exécute cette ligne juste avant de la quitter" - parfait pour fermer un fichier, une connexion, ou libérer une ressource.

    Décorticage mot par mot
    defer fmt.Println("fermeture")
    • defer"Reporte cette instruction à la toute fin de la fonction" - elle n'exécute PAS immédiatement, elle est mise de côté.
    Exemples progressifs
    1 · le plus simple
    func main() { fmt.Println("1") defer fmt.Println("2 (différé)") fmt.Println("3") }
    2 · cas concret
    func lireFichier() { fmt.Println("ouverture du fichier") defer fmt.Println("fermeture du fichier") fmt.Println("lecture en cours...") }

    Résultat : ouverture du fichier → lecture en cours... → fermeture du fichier. La fermeture est garantie, même si la fonction a plusieurs points de sortie.

    3 · cas limite

    Plusieurs defer s'empilent et se rejouent dans l'ordre inverse (le dernier annoncé est le premier joué) :

    defer fmt.Println("A") defer fmt.Println("B") defer fmt.Println("C") // à la fin de la fonction, affiche : C puis B puis A
    Piège classique

    Croire que les defer s'exécutent dans l'ordre où ils sont écrits. En réalité c'est une pile : dernier entré, premier sorti (LIFO).

    Quiz éclair

    defer Println("A") ; defer Println("B") - dans quel ordre s'affichent-ils à la fin de la fonction ?

    04.2

    Les tableaux (arrays) : des cases numérotées, en nombre fixe

    Le problème de la vraie vie

    Un casier de piscine numéroté : le nombre de casiers est décidé une fois pour toutes à la construction du bâtiment - tu ne peux pas en ajouter un 51e si le mur en contient 50. Un tableau (array) en Go, c'est exactement ça : une suite de cases numérotées, dont le nombre est fixé pour toujours dès que tu l'écris - il fait partie du type lui-même, pas juste une info à côté.

    C'est la brique la plus simple pour ranger plusieurs valeurs. Tu verras au module 05.2 la slice, qui ressemble à un tableau mais peut grandir - retiens bien la différence : tableau = taille gravée dans le marbre, slice = sac extensible.

    3 cases numérotées de 0 à 2 - la case "3" n'a jamais existé, même si "3" apparaît dans le type.
    Décorticage mot par mot
    var notes [3]int notes[0] = 12 notes[1] = 15 fmt.Println(notes[0])
    • [3]int"Un tableau de EXACTEMENT 3 cases, chacune contenant un int" - le nombre 3 fait partie du type : [3]int et [4]int sont deux types différents, pas la même chose avec une case en plus.
    • notes[0]Accès à la case d'index 0 - Go compte à partir de 0, pas de 1. Pour un tableau de 3 cases, les index valides sont 0, 1 et 2 - jamais 3.
    • notes[0] = 12Écrit 12 dans la première case. Contrairement à une string (voir plus bas), une case de tableau se réécrit librement.
    Exemples progressifs
    1 · le plus simple

    Un tableau non initialisé n'est jamais "vide" en Go - il est rempli de la valeur zéro du type (0 pour int) :

    var scores [3]int scores[0] = 7 fmt.Println(scores)
    2 · cas concret

    3 contrôles dans l'année : un nombre fixe et connu à l'avance - le cas d'usage idéal pour un tableau plutôt qu'une slice :

    notes := [3]int{12, 15, 8} total := 0 for i := 0; i < len(notes); i++ { total = total + notes[i] } fmt.Println("Total :", total)
    3 · cas limite

    Accéder à un index en dehors du tableau :

    notes := [3]int{12, 15, 8} fmt.Println(notes[3]) // panic: runtime error: index out of range [3] with length 3
    Piège classique

    Confondre "un tableau de 3 cases" avec "les index vont de 1 à 3". En Go (et dans la quasi-totalité des langages), un tableau de taille N a des index valides de 0 à N-1. notes[3] sur un tableau de 3 cases est TOUJOURS invalide, aucune exception.

    Piège classique - une string n'est PAS un tableau

    On pourrait croire qu'une string est juste "un tableau de caractères" comme dans d'autres langages. En Go, ce n'est pas le cas : une string est une suite immuable d'octets (pas de caractères). Conséquences concrètes :

    mot := "café" fmt.Println(mot[0]) // 99 : un OCTET (le code de 'c'), pas "c" mot[0] = 'C' // ERREUR : cannot assign to mot[0] (strings immuables)

    Rappelle-toi aussi le module 05.1 : len("café") vaut 5, pas 4, car "é" prend 2 octets - encore une preuve qu'une string se comporte différemment d'un tableau de lettres. Pour manipuler du texte lettre par lettre, on convertit en []rune (vu en 05.1), jamais en indexant la string directement.

    Bac à sablechange les valeurs ou l'index, observe le résultat
    notes := [3]int{12, 15, 8} total := 0 for i := 0; i < len(notes); i++ { total = total + notes[i] } fmt.Println("Total :", total) fmt.Println("Deuxième note :", notes[1])
    Quiz éclair

    notes est un [3]int déjà rempli. Que se passe-t-il si tu essaies notes = append(notes, 20) ?

    04.4

    Patron : Menu interactif (for + switch)

    Pourquoi ce patron revient tout le temps

    Presque tous les programmes CLI (dont le Projet RED) tournent en boucle en proposant un menu, jusqu'à ce que l'utilisateur choisisse de quitter. C'est la combinaison for (répéter) + switch (aiguiller) qui rend ça possible.

    for { fmt.Println("1. Jouer 2. Quitter") fmt.Scan(&choix) switch choix { case 1: jouer() case 2: return } }
    04.5

    Patron : Recherche / Filtrage (for + if)

    Pourquoi ce patron revient tout le temps

    "Trouve tous les élèves admis" ou "trouve le plus grand score" nécessite de parcourir chaque élément d'une collection et de tester une condition sur chacun. C'est le patron for + if.

    for _, note := range notes { if note >= 10 { fmt.Println("Admis :", note) } }
    04.6

    Patron : Validation de saisie (for + Scan + if)

    Pourquoi ce patron revient tout le temps

    Rappelle-toi le module 00.1 : si l'Entrée est invalide, tout le reste s'effondre. Ce patron répète la demande de saisie jusqu'à obtenir une valeur acceptable, au lieu de faire planter ou continuer avec des données fausses.

    var age int for { fmt.Scan(&age) if age > 0 { break // saisie valide → on sort enfin } fmt.Println("Âge invalide, réessaie") }

    Texte et collections de données

    Un seul nombre ou un seul mot ne suffit presque jamais dans un vrai programme. Ce module te donne les outils pour manipuler du texte finement et pour ranger plusieurs valeurs ensemble.

    05.1

    Manipuler du texte : string, rune, package strings

    Le problème de la vraie vie

    Un formulaire où l'utilisateur tape " Léa " (avec des espaces en trop) ou "LEA" en majuscules doit quand même reconnaître "Léa". Le package strings fournit des outils tout prêts pour nettoyer et transformer du texte, sans réinventer la roue caractère par caractère.

    Décorticage mot par mot
    propre := strings.TrimSpace(" ynov ") maj := strings.ToUpper(propre)
    • strings.Le préfixe qui dit "va chercher cet outil dans la boîte à outils strings" - nécessite import "strings".
    • TrimSpace"Coupe les espaces" - retire les espaces en début et fin de chaîne (pas au milieu).
    • ToUpperRenvoie une nouvelle chaîne toute en majuscules - ne modifie jamais l'originale (une string est immuable en Go).
    Exemples progressifs
    1 · le plus simple
    nom := " ynov " propre := strings.TrimSpace(nom) fmt.Println(propre, len(propre))
    2 · cas concret

    Rendre une saisie utilisateur insensible à la casse pour la comparer :

    motDePasse := "SecuriteYnov" saisie := "securiteynov" if strings.ToLower(motDePasse) == strings.ToLower(saisie) { fmt.Println("Accès autorisé") }
    3 · cas limite

    string vs rune - un caractère accentué n'est pas forcément 1 seul octet :

    mot := "café" fmt.Println(len(mot)) // 5 : "é" prend 2 octets en UTF-8 ! fmt.Println(len([]rune(mot))) // 4 : en runes, on compte bien 4 lettres
    Piège classique

    len() sur une string compte des octets, pas des lettres. Avec des caractères accentués ou spéciaux, convertis en []rune d'abord si tu veux compter de vraies lettres.

    05.2

    Arrays vs Slices

    Le problème de la vraie vie

    Si tu as 100 joueurs dans ton jeu, tu ne vas pas créer 100 variables joueur1, joueur2... C'est impossible à gérer ! Une slice est un sac extensible : tu peux y entasser autant d'éléments que tu veux, dans l'ordre, et le sac grandit tout seul.

    append ne modifie pas le sac sur place : il renvoie un NOUVEAU sac, plus grand, qu'il faut réaffecter (notes = append(...)).
    Décorticage mot par mot
    notes := make([]int, 0) notes = append(notes, 15)
    • []int"Une slice d'int" - les crochets vides (sans nombre dedans) signalent une taille libre, contrairement à [3]int (un array figé à 3 cases).
    • make(...)Crée la slice vide, prête à recevoir des éléments.
    • append(...)"Ajoute un élément à la fin" - renvoie une nouvelle slice qu'il faut réaffecter à la variable (d'où notes = append(notes, ...), pas juste append(notes, ...) seul).
    Exemples progressifs
    1 · le plus simple
    notes := make([]int, 0) notes = append(notes, 15) notes = append(notes, 8) fmt.Println(notes, len(notes))
    2 · cas concret

    100 joueurs sans créer 100 variables :

    var joueurs []string joueurs = append(joueurs, "Léa") joueurs = append(joueurs, "Sam") joueurs = append(joueurs, "Yanis") fmt.Println("Nombre de joueurs :", len(joueurs))

    Résultat : Nombre de joueurs : 3 - et ça marcherait pareil avec 3 ou avec 3000 joueurs, sans changer une ligne de logique.

    3 · cas limite

    Accéder à un index qui n'existe pas :

    notes := []int{10, 12} fmt.Println(notes[5]) // panic: runtime error: index out of range [5] with length 2
    Piège classique

    Contrairement aux maps (05.4), accéder à un index de slice qui n'existe pas fait planter le programme (panic), pas de valeur zéro silencieuse. Toujours vérifier len(slice) avant d'accéder à un index dynamique.

    Quiz éclair

    notes a 2 éléments. Que se passe-t-il avec notes[5] ?

    05.3

    Parcourir une collection : for ... range

    Le problème de la vraie vie

    Corriger 30 copies veut dire regarder chaque copie une par une, dans l'ordre. range fait ça pour toi : il te donne automatiquement l'index et la valeur de chaque élément, sans que tu aies à gérer un compteur toi-même comme avec for i := 0; i < len(x); i++.

    Décorticage mot par mot
    for index, valeur := range notes { fmt.Println(index, valeur) }
    • range notes"Parcours chaque élément de notes" - fonctionne sur les slices, arrays, strings et maps.
    • index, valeurÀ chaque tour, index reçoit la position (0, 1, 2...) et valeur le contenu à cette position.
    • _Si tu n'as besoin que de la valeur, remplace index par _ (déjà vu en module 04.4) pour dire "j'ignore volontairement cette valeur".
    Exemples progressifs
    1 · le plus simple
    notes := []int{12, 15, 8} for index, valeur := range notes { fmt.Println(index, "->", valeur) }
    2 · cas concret

    Calculer une moyenne en parcourant les notes, en ignorant l'index :

    notes := []int{12, 15, 8, 17} total := 0 for _, valeur := range notes { total += valeur } moyenne := float64(total) / float64(len(notes)) fmt.Println("Moyenne :", moyenne)
    3 · cas limite

    Modifier valeur dans la boucle ne modifie PAS la slice d'origine :

    notes := []int{10, 20} for _, valeur := range notes { valeur = valeur * 2 // modifie seulement la COPIE locale } fmt.Println(notes) // toujours [10 20], inchangé !
    Piège classique

    valeur dans un range est une copie de l'élément, pas l'élément lui-même. Pour modifier réellement la slice, il faut utiliser l'index : notes[index] = valeur * 2.

    05.4

    Les maps : dictionnaires clé -> valeur

    Le problème de la vraie vie

    Un carnet d'adresses ne cherche pas un contact par sa position dans la liste, mais par son nom. Une map associe directement une clé (le nom) à une valeur (le numéro), avec un accès quasi instantané - pas besoin de parcourir toute la liste comme avec une slice.

    Décorticage mot par mot
    ages := map[string]int{"Léa": 20} ages["Sam"] = 22
    • map[string]int"Une map dont les clés sont des string et les valeurs des int" - les deux types sont fixés à la création.
    • ages["Sam"] = 22Ajoute (ou remplace) l'entrée pour la clé "Sam" - pas besoin d'append, l'accès par clé suffit.
    Exemples progressifs
    1 · le plus simple
    ages := map[string]int{"Léa": 20, "Sam": 22} fmt.Println(ages["Léa"])
    2 · cas concret

    Compter les votes pour un sondage :

    votes := map[string]int{} votes["Go"]++ votes["Go"]++ votes["Python"]++ fmt.Println(votes["Go"], votes["Python"])
    3 · cas limite

    Lire une clé qui n'existe pas ne plante jamais :

    ages := map[string]int{"Léa": 20} fmt.Println(ages["Nora"]) // affiche 0, pas d'erreur valeur, existe := ages["Nora"] fmt.Println(valeur, existe) // 0 false : la 2e valeur confirme l'absence
    Piège classique

    Contrairement aux slices (05.2) qui paniquent sur un index invalide, une map renvoie silencieusement la valeur zéro du type pour une clé absente (0 pour int, "" pour string...). Utilise la forme à deux valeurs valeur, existe := map[cle] quand tu dois vraiment savoir si la clé existe.

    Quiz éclair

    ages ne contient pas la clé "Nora". Que renvoie ages["Nora"] ?

    06

    Pointeurs, structures & temporisation

    On va enfin comprendre pourquoi certaines fonctions modifient vraiment tes variables et d'autres non, savoir décrire des objets du monde réel avec des struct, et apprendre à faire attendre ton programme.

    06.1

    Pointeurs : * et &, valeur vs référence

    Le problème de la vraie vie

    Donner une photocopie d'un document à quelqu'un : s'il écrit dessus, l'original dans ton tiroir reste intact. Donner l'original : s'il écrit dessus, c'est définitif, tu le retrouveras modifié. Par défaut, Go donne toujours une "photocopie" (une copie) aux fonctions. Un pointeur, c'est donner l'adresse du tiroir plutôt qu'une photocopie - la fonction peut alors modifier le document original.

    n stocke l'adresse de x, pas sa valeur - *n permet d'aller lire ou écrire à cette adresse.
    Décorticage mot par mot
    func ajouterUn(n *int) { *n = *n + 1 } ajouterUn(&x)
    • *int(dans le paramètre) "Un pointeur vers un int" - n ne contient pas un nombre, mais l'adresse d'une boîte qui contient un nombre.
    • *n(dans le corps) "Va voir ce qu'il y a à l'adresse contenue dans n" - déréférence le pointeur pour lire ou écrire la vraie valeur.
    • &x(à l'appel) "L'adresse de x" - crée le pointeur qu'on transmet à la fonction.
    Exemples progressifs
    1 · le plus simple
    func sansPointeur(n int) { n = n + 1 // modifie seulement la copie locale } x := 5 sansPointeur(x) fmt.Println(x) // affiche 5, inchangé
    2 · cas concret
    func ajouterUn(n *int) { *n = *n + 1 } x := 5 ajouterUn(&x) fmt.Println(x) // affiche 6, vraiment modifié
    3 · cas limite

    Oublier le * pour déréférencer :

    func ajouterUn(n *int) { n = n + 1 // ERREUR : n est une adresse, +1 n'a pas de sens sur une adresse }
    Piège classique

    Confondre n (l'adresse elle-même) et *n (la valeur à cette adresse). C'est exactement le même symbole * que dans le type du paramètre, mais avec un rôle différent selon le contexte - normal que ça prenne un peu de temps à devenir intuitif.

    Quiz éclair

    Pourquoi func f(n int) { n = 99 } ne modifie-t-elle jamais la variable passée en argument ?

    06.2

    Créer un type complexe : struct

    Le problème de la vraie vie

    Une fiche élève a un nom ET un âge ET des notes - des informations de nature différente mais qui décrivent une seule et même personne. Une struct regroupe ces champs disparates sous un seul type, comme une vraie fiche cartonnée avec plusieurs champs à remplir.

    Décorticage mot par mot
    type Etudiant struct { Nom string Age int } e := Etudiant{Nom: "Léa", Age: 20}
    • type ... struct"Je crée un nouveau type nommé Etudiant, qui est une structure."
    • Nom stringUn champ : chaque struct est une liste de champs, chacun avec son propre type.
    • Etudiant{...}Crée une instance concrète du type, en remplissant les champs par leur nom.
    • e.Nom(pour lire ensuite) Le point accède à un champ précis de l'instance - déjà vu avec fmt.Println.
    Exemples progressifs
    1 · le plus simple
    type Etudiant struct { Nom string Age int } e := Etudiant{Nom: "Léa", Age: 20} fmt.Println(e.Nom, e.Age)
    2 · cas concret

    Modifier un champ après création :

    e := Etudiant{Nom: "Sam", Age: 19} e.Age = 20 // anniversaire ! fmt.Println(e.Age)
    3 · cas limite

    Copier une struct copie TOUS ses champs (comme un int simple, pas comme une slice) :

    e1 := Etudiant{Nom: "Léa", Age: 20} e2 := e1 // copie complète et indépendante e2.Age = 99 fmt.Println(e1.Age, e2.Age) // 20 99 : e1 n'a pas bougé
    Piège classique

    Croire que e2 := e1 crée un simple "alias" vers la même struct. En réalité c'est une copie complète et indépendante - modifier e2 ne touche jamais e1 (sauf si on utilise des pointeurs vers structs, une nuance pour plus tard).

    06.3

    Combiner struct + slice

    Le problème de la vraie vie

    Un élève n'a pas qu'une seule note dans l'année, il en a plusieurs. Une struct peut très bien contenir une slice comme champ - combinant "plusieurs infos liées" (struct) et "collection dynamique" (slice) en une seule structure de données cohérente.

    Exemples progressifs
    1 · le plus simple
    type Etudiant struct { Nom string Notes []int } e := Etudiant{Nom: "Sam", Notes: []int{12, 15}} fmt.Println(e.Notes)
    2 · cas concret

    Ajouter une note après coup avec append (05.2), directement sur le champ :

    e := Etudiant{Nom: "Sam", Notes: []int{12, 15}} e.Notes = append(e.Notes, 18) fmt.Println(e.Notes) // [12 15 18]
    3 · cas limite

    Une slice non initialisée dans une struct vaut nil, mais reste utilisable avec append :

    var e Etudiant // Notes vaut nil, pas une erreur e.Notes = append(e.Notes, 10) // append gère nil tout seul, ça marche ! fmt.Println(e.Notes) // [10]
    Piège classique

    Craindre d'utiliser une slice "vide par défaut" (nil). Contrairement à d'autres langages où ça planterait, append sur une slice nil fonctionne très bien en Go et crée la slice à la volée.

    06.4

    Gérer le temps : package time et time.Sleep

    Le problème de la vraie vie

    Un écran de chargement qui affiche "Patiente..." doit vraiment faire une pause avant d'afficher la suite, sinon l'utilisateur ne voit jamais le message. time.Sleep met le programme en pause pendant une durée précise.

    Décorticage mot par mot
    time.Sleep(2 * time.Second)
    • time.SecondUne valeur spéciale du package time représentant "1 seconde" - se multiplie par un nombre pour composer une durée.
    • Sleep(...)"Mets le programme en pause pour cette durée" - rien d'autre ne s'exécute dans cette fonction pendant ce temps.
    Exemples progressifs
    1 · le plus simple
    fmt.Println("Chargement...") time.Sleep(2 * time.Second) fmt.Println("Prêt !")
    2 · cas concret

    Une pause différente selon une variable, pour simuler un temps de traitement variable :

    delai := 500 // millisecondes time.Sleep(time.Duration(delai) * time.Millisecond)
    3 · cas limite

    Oublier la conversion de type explicite (rappel du module 01.3) :

    delai := 500 time.Sleep(delai * time.Millisecond) // ERREUR : delai est int, time.Millisecond est time.Duration
    Piège classique

    Le même principe que 01.3 revient ici : Go ne mélange jamais deux types différents sans conversion explicite, même quand l'un des deux est un simple nombre "déguisé" comme time.Duration.

    Structurer un projet Go sur plusieurs fichiers

    Le problème de la vraie vie

    Piège classique
